# Excel compatibility and operating limits

All 261 requested functions have executable implementations, with 40 additional ready-made workflows. The complete, generated per-function record is [FUNCTION_COVERAGE.md](FUNCTION_COVERAGE.md) or [function-coverage.json](function-coverage.json).

These are material limits rather than claims of universal Excel equivalence:

- Calculations use JavaScript double precision. Very large identifiers are text; numeric precision is not silently promised beyond that representation. Round only through explicit rounding operations or for display.
- The calculation date model is Excel's 1900 serial system, including its artificial serial 60. ISO date text and explicit import date order avoid locale guessing. ExcelJS reads workbook date systems on import. Volatile TODAY/NOW use the calculation clock in UTC; results are stored until explicitly recalculated. Time-only strings are supported. DATEVALUE does not guess arbitrary localized date descriptions.
- TEXT supports the implemented numeric, percentage, currency, scientific, date, and time masks. Exotic fraction, conditional/color/locale, and elapsed-time masks report a limitation/error instead of an invented formatted value. CHAR/CODE use Windows-1252, which differs from legacy Mac code pages.
- LOOKUP supports vector lookup; exact/approximate modes and sorted-data requirements are explicit. Reference functions use the local workbook and supported A1/R1C1 references; external/named workbook references are unsupported. ISFORMULA/FORMULATEXT reflect imported metadata, not ordinary values.
- LINEST/LOGEST reject redundant predictors with an explicit error rather than silently removing predictors. Research workflows require appropriate sample assumptions; p-values do not establish causation.
- Rates are decimal per-period rates in the low-level financial functions unless stated otherwise. The loan workflow provides annual percentage, periods per year, term, and payment timing. Cash-flow signs, day-count bases, invalid schedules, and non-convergence are explicit. IRR-type problems may have multiple mathematically valid roots; a returned root does not establish uniqueness.
- Dynamic-array outputs are result values. They are added to a new worksheet or explicitly appended as columns, so they do not overwrite occupied source cells. Recursive lambdas and nested-array spills are outside the supported visual-operation model. Appended output aligns by result row order; it is not an inferred database join.
- GETPIVOTDATA summarizes the selected local table with explicit fields, filters, and aggregation; it is not a parser for arbitrary Excel PivotTable caches. CUBEVALUE/CUBEMEMBER use the actual configured provider interface. The bundled local demo is not a production Excel/SSAS connector. Production connections need the corresponding adapter, infrastructure, and credentials.
- Uploaded formulas use cached values, with original formula metadata retained where available. No macros, arbitrary scripts, or external links run. Missing cached values are reported. Executable Excel formulas are not exported; exports contain calculated results/literal values.
- XLSX and project files preserve typed identifiers. CSV has no formal type schema and cannot force another spreadsheet application to preserve identifiers; import columns as text there, or use XLSX/projects. Formula-like CSV text receives a protective apostrophe; reopening CSV therefore retains that safety prefix. XLSX strings remain explicitly literal.
- Currency type does not imply a currency or exchange rate. The generic `¤` marker preserves currency formatting without assuming USD. Set units in column names and use explicit conversion inputs when needed.
- Imports are limited to 20 MB and 250,000 cells; ZIP entry sizes are validated before XLSX loading. Projects are limited to 20 MB/one million validated cells. Workers keep calculations/imports separate from UI work, but the editable table uses 100-row pages and is not fully virtualized across columns. Split very large datasets for practical editing performance.
- Local browser storage is explicitly saved, limited by the browser, and specific to the current origin. Download a full project for durable backups and portable reopening. Undo history is in memory and applies to workbook edits; downloaded projects preserve calculation history and operations.

No production analytical connection or paid API is required for the core application. No exhaustive certification against every Excel version, locale, file type, and floating-point edge case is claimed.
